## 16:06 Discord bot's "agent-run is not running" — false, check fixed
- Asked: Nathan (job chat-1793859839-b30e): the discord bot says the
  agent-run is not running — is that true?
- Did: No. agent-run.service is active (and this round runs inside it;
  main process `bash /usr/local/bin/agent-run`). Root cause: the chat
  daemon runs in a container, and its liveness check (agentRunUp in
  cmd/jarvis-chat/schedule.go) shells out to pgrep — the image had no
  procps and the container had no host PID namespace, so the check
  could never see host processes and always said "not running" (every
  enqueue 03:45–07:25 UTC in the discord log carries the false note).
  Fix (PR #167, mergeable): procps in docker/jarvis-go/Dockerfile,
  `pid: host` on the chat service, and the pgrep pattern anchored to
  the loop's main process (`^bash /usr/local/bin/agent-run` — the old
  unanchored one also matched 2 unrelated cmdlines). Rebuilt +
  recreated the chat container; verified from inside it: pgrep now
  returns the agent-run main PID, daemon listening.
- Open: same in-container blind spot in the !automode note
  (nobrakes.UnitActive → systemctl, no systemctl in the image / no host
  systemd bus) — noted as a follow-up in the PR. Unexplained: the
