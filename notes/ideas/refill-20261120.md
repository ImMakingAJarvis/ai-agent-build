## What I picked, and why

The queue is big (81 ready) and mostly build work, so the backlog's job
right now is the opposite: **decisions and audits the build queue does not
answer**. Six of the eight entries are "read the stack, write a judgment
note"; none produce code.

1. **queue-sequencing** — 81 ready jobs across six workstreams will be
   consumed strictly by priority, which risks interleaving badly: a Q1 brain
   switch mid-Reel, branch contention on the shared reel branch, photo/bench
   VRAM windows colliding with builds. Nobody has sequenced this; a note
   with an order + the conflicts is the highest-leverage think I could
   write tonight.
2. **brain-upgrade-gate** — Q1 (pull qwen3.8-27b and switch) and moe-scout's
   35B-A3B recommendation both converge on "replace the brain," but there is
   no agreed gate: what must be proven, VRAM/ctx fit, swap procedure,
   rollback. Q1.3 says "ask Nathan first" — this note is what makes that
   ask answerable in one read.
3. **lan-security-audit** — the dashboard has no password (e2-7 is queued to
   add one, which confirms the gap), and Plane/Jellyfin/Grafana/Prometheus/
   the engines are all on the LAN with varying auth. No entry has inventoried
   the whole surface and the hardening order.
4. **jarvis-ha-mqtt-trace** — two finished notes (power-economics,
   ha-automation-ideas) independently found the `jarvis_*` HA sensors are
   missing and the publisher inactive since 10-27. That is now a confirmed
   two-witness finding with no queued fix — trace the publish path and list
   the fix. It gates three of the five ha-automation ideas.
5. **discord-bot-minimum** — D1–D8 + r1 is ~30 queued jobs, the largest
   single block in the queue. A "minimum useful v1" note tells the loop (and
   Nathan) what to build first and what defers, before the queue's priority
   order starts building D8 before D1's reliability floor.
6. **cpu-load-audit** — the snapshot shows load 34–35 sustained, which is
   high and unexplained. Worth knowing what generates it (workers? reindex?
   engine?) and whether games/voice need capping before the parked
   game-startup job hits it.
7. **game-gpu-coexistence** — there is an automatic swap window for photos
   but no documented policy for games (a parked job is debugging a game
   startup failure; "a game gets the GPU" is a standing rule with no
   procedure). The note defines what happens today and the recommended yield
   procedure.
8. **agent-cost-ledger** — power-economics left the $/kWh rate unconfirmed
   against the bill, and API spend has no weekly roll-up anywhere. A cost
